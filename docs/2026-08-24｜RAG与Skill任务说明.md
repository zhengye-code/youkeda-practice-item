# 2026-08-24｜RAG 与 Skill 任务说明

## 1. 基础概念

- Function Calling：模型选择并调用代码工具，适合天气、时间、计算等明确动作。
- RAG：先检索外部资料，再把相关片段加入 Prompt，适合回答模型原本不知道的项目私有知识。
- Skill：固化一类任务的步骤和验收规则，适合学习复盘、日报生成、资料入库等重复业务流程。

三者的关系不是互相替代：Skill 规定流程，Function Calling 执行动作，RAG 提供有来源的知识上下文。

## 2. 为什么当前项目要加入 Skill 和 RAG

原有三个工具只能完成原子动作。它们不负责稳定执行多步骤业务流程，也无法直接读取课程或项目私有资料。

加入 Skill 后，“学习复盘”不再依赖模型每次临时理解流程；加入 RAG 后，知识类问题会先查本地 Markdown，再让模型依据资料回答。这样比只依赖通用模型更可控，也更容易核查来源。

## 3. 本次实现

### 自定义 Skill

实现 `StudyReviewSkill`，触发词为“学习复盘”“今日复盘”“复盘学习”。命中后直接执行固定五步流程：

1. 核心概念。
2. 可核查产出。
3. 测试和验收证据。
4. 问题与证据缺口。
5. 下一步最小行动。

### 极简关键词 RAG

`KeywordRagService` 完成以下流程：

```text
加载 knowledge-base/*.md
→ 按空行切分片段
→ 提取英文关键词和中文二元词
→ 计算匹配分数
→ 返回 Top K 片段和来源
→ 拼入增强 Prompt
```

这是教学用最小版本，不包含 Embedding、向量数据库或 Rerank，但已经跑通“文档—检索—上下文—回答”的完整链路。

### 完整消息路由

微信文本消息和语音转写文本使用同一套路由，顺序为：

```text
命中 Skill 关键词 → Skill 执行 → 回复
否则，RAG 开启且命中 RAG 关键词 → 检索 → 增强 Prompt → LLM 回复
否则 → 原有 chatWithTools → 工具调用或普通闲聊
```

Skill 放在 RAG 前面，可以避免一条同时包含“学习复盘”和“RAG”的消息被知识检索抢走。

## 4. 开关对比

配置项：

```properties
rag.enabled=${RAG_ENABLED:true}
```

同一个问题“RAG、Skill 和 Function Calling 有什么区别？”：

- `RAG_ENABLED=true`：路由类型为 `RAG`，Prompt 中含检索片段和 `rag-skill-notes.md` 来源。
- `RAG_ENABLED=false`：路由类型为 `DIRECT_LLM`，直接进入原有 `chatWithTools`。

该对比由 `MessageRouterTest` 离线验证，不依赖真实百炼 API。
